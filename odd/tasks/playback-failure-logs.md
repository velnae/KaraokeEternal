**Goal**: Record actionable, safe server-side diagnostics when an authorized player reports a failed YouTube queue item. T1 implementation and verification are complete; activation on the running service is a separate, pending step.

- At baseline, `YouTubePlayer.tsx` surfaced API-loader errors and mapped iframe codes 2/5/100/101/150 into display text; `PlayerController.tsx` settled YouTube failures once and dispatched `playerFailure({ queueId, error: msg })`. `src/store/socketMiddleware.ts` carried `PLAYER_EMIT_FAILURE` to `server/Player/socket.ts`, which checked admin + authoritative player, transitioned to FAILED, acknowledged, and pushed the changed queue, but discarded `error`. `Queue.transition` returns false for missing, repeated, or invalid transitions. `Queue.get(roomId).entities[queueId]` supplies the persisted `source` and `externalId` (video identifier).

This is not evidence of the running process's effective level or activation. `KES_PATH_DATA` configures the database, not this logger path; `server/lib/test-setup.ts` disables test file logging by default.
